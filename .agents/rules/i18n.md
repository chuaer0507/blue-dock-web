# 国际化规范

## 架构分工

```
@blue-dock/i18n          →  语言包、t()、I18nProvider
apps / app               →  组装注入；切换语言刷新壳层文案
```

## 翻译文件位置（目标）

```
packages/i18n/locales/
├── zh/          # 文件目录（中文资源）
│   ├── common.json
│   └── …
└── en/          # 文件目录（英文资源）
    └── ...
```

运行时 locale key：**`zh-CN` / `en-US`**（`AppLanguage`）；localStorage `i18nextLng` 与 `users.lang` / `Accept-Language` 同值。**不接受**短码 `zh`/`en`。

命名空间按 **feature** + `common`（非多收银 app）。

## 主题

主题仅本地：`localStorage['blue-dock-theme']` = `light` | `dark` | `system`；不写后端。

## 使用方式

```tsx
import { useTranslation } from 'react-i18next';
const { t } = useTranslation('task');
return <Button>{t('list.title')}</Button>;
```

- 用户可见文案禁止硬编码
- Toast / Modal **内部**已翻译时，调用方勿双层 `t()`
- 歧义短词加上下文前缀，如 `[weekday].一`

## 动态内容

项目名、昵称、任务标题等用后端字段，不进语言包。  
微应用由宿主注入 `lang`。

## Key 规范

- 推荐点号分层：`task.list.title`、`messenger.composer.send`
- 或全仓统一「中文原文即 key」——二选一，见 `docs/guide/i18n-and-theme.md`
- 中英同步；先加中文再补英文（若用稳定英文 key）

## CI 检查（落地后）

```bash
bun run i18n-extract   # 扫描未用 t() 包裹的硬编码文案
```

## 语言持久化

- 用户选择存 `localStorage`（按用户隔离）
- 首次默认跟随 `navigator.language`
- 设置页：`/manage/setting/language`

详情：`docs/guide/i18n-and-theme.md`
